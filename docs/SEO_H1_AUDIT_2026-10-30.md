# JKTL missing-H1 fixes — 30 October 2026

## Findings and shared fixes

- Main template previews had no H1 in the outer document. Their iframe had a separate website heading, which does not supply the preview page's primary heading. TemplatePreview now renders one visible name/category-based H1 and a short descriptive introduction outside the frame, on desktop and mobile. Preview/navigation/device controls and selection links are preserved.
- Business login/signup forms already contained H1 elements, but client-only search-parameter handling under Suspense exposed only loading fallback HTML to non-rendering crawlers. Server page wrappers now await request query parameters and pass them to the existing client forms. The actual form/H1 is server rendered, with the existing design and redirect behavior.
- A shared auth metadata helper adds explicit noindex/nofollow and stable, query-free canonicals. It is used for login, signup, onboarding and password/account-access routes. Valid template selections and existing invite/product/referral query semantics are retained.
- Template page metadata now has unique name/category-based titles, descriptions, canonicals, consistent Open Graph data and WebPage/BreadcrumbList JSON-LD. No review, offer or price claims were invented.

## Validation

- Targeted ESLint and TypeScript checks passed in both repositories. Main's obsolete next lint script was bypassed using its installed Next ESLint configuration directly; the lint script itself was left unchanged.
- All **207 generated Main template HTML pages** were parsed: exactly one meaningful H1 per outer document, unique titles/descriptions, correct canonicals and WebPage structured data.
- **40 Business raw-HTML authentication variants** were checked: login and signup for 20 representative template IDs. Each returned HTTP 200, one H1, explicit noindex and the query-free route canonical.
- Chromium verified desktop/mobile heading visibility, no horizontal overflow, unchanged selection links and device controls, login/signup navigation retaining template IDs, signup-to-onboarding handoff and demo-to-editor redirect. Signup stopped before account creation; no real account/payment was created.

- Existing SEO-indexing, template-catalog and website-template regression suites passed. Generated tenant sitemap paths were checked to exclude platform login/signup/template query URLs.
